Core Features & Technical Functionality

A. Account Creation & Dual-Verification Authentication

Functionality: Users register using a phone number and an email address to ensure account security.

Mechanism: Phone number verification via Firebase Phone Authentication (SMS OTP). Email address verification via a 6-digit confirmation code.

Data Involved: Phone number, email address, unique user ID (UUID), and device installation identifier (device_id).

B. Local-First Financial Data Storage

Functionality: Users can manually log transactions, create categories, establish envelope budgets, and set savings goals.

Mechanism: All financial records are immediately saved to a local SQLite database (Drift) on the user's physical device.

Data Involved: Transaction titles, amounts, currencies, timestamps, payment methods, transaction types (income/expense), category names, envelope target amounts, and goal progress.

C. Automated Financial SMS Processing (Android / iOS)

Functionality: Automatically detects and drafts transaction entries from incoming banking and digital wallet SMS messages.

Mechanism: Android uses a local background broadcast listener (RECEIVE_SMS / READ_SMS) to extract transaction details (amount, currency, merchant) using local regular expression (Regex) pattern matching. iOS uses user-initiated Apple Shortcuts integration via URL schemes (payzabt://process-sms).

Privacy Safeguard: Parsing happens 100% locally on the device. Non-financial messages are completely ignored. SMS message content is never uploaded to external servers.

D. Cloud Synchronization Engine

Functionality: Keeps user data backed up and synchronized across multiple logged-in devices.

Mechanism: Uses an offline-first SyncOutbox queue pattern. Local mutations (create, update, delete) are logged locally and pushed to the cloud server via HTTPS when an internet connection is available. Implements Soft Delete (deleted_at tombstones) to synchronize deletions across devices before local database cleanup.

Data Involved: Encrypted financial records, operation timestamps, sequence IDs (sync_cursor), and operation status logs.

E. Analytics & Insights

Functionality: Generates visual reports (charts, monthly spending trends, category breakdowns).

Mechanism: Queries data directly from the local SQLite database. Optional AI models (e.g., Gemini API) may process anonymized transaction titles locally/cloud-side to suggest automatic categories.

Sensitive System Permissions Required

To operate its core features, PayZabt requests the following system permissions:

  • RECEIVE_SMS / READ_SMS (Android): Essential for automatic parsing of banking transaction alerts. Used strictly for financial SMS detection. No personal or promotional SMS messages are read, saved, or uploaded.
  • INTERNET & ACCESS_NETWORK_STATE: Required for Firebase authentication checks, background database sync, and connectivity status monitoring.
  • POST_NOTIFICATIONS: To send local budget alert reminders (e.g., overspending warnings) and goal achievement notifications.

Security & Data Retention Policies

  • Data Encryption: All network communication between the app and backend services uses TLS/HTTPS encryption. Local SQLite databases are stored in secure application-private sandboxes.
  • Data Retention: Personal and financial data is retained as long as the user maintains an active account.
  • Account & Data Deletion: Users can request full account and data deletion through the app settings or via a web contact form. Upon deletion, all cloud database records associated with the User ID are permanently purged, and local database files are wiped from the device upon logout.
